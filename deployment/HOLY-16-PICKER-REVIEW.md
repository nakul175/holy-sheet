# Scoped connected search in the existing HS-owned SHO picker

Link mode now submits an explicit private JSON query to the existing connected-search contract. Workspace and optional space are explicit; without a valid project location, link mode requires the user to choose a workspace rather than silently using the first one. Results use the existing 20-item actor/query/scope-bound cursor, and title/path/snippet text is rendered safely. The current page is read again by the existing picker selection endpoint before only page/space IDs are sent to the approved SHO origin and channel. Search itself never links or shares a page.

The picker initially loads only accessible workspace/space metadata (`metadataOnly=1`), with no page directory. Legacy API callers that omit this flag remain compatible. Page creation and space creation retain their existing authority rules. No metadata is fetched when restrictive account/channel context is missing.

The optional connected-frame account header restricts the already authenticated HS user; it cannot authenticate or impersonate another user. A mismatch fails before querying. Responses identify their actual subject and request UUID. Query changes, scope changes, logout or account changes clear old snippets and abort/ignore late responses. Unknown requests retain their exact cursor/query/correlation ID for explicit retry. All requests remain no-store, same-origin for cookies, and use the existing verified HS audience for bearer clients. No tokens cross the host frame boundary, no CORS expansion or new delegation is introduced.

The current backend's 1,000-match snapshot bound, 60-per-user-per-minute limiter, five-minute cursor life, ranking and current-access checks are unchanged. This does not claim a new indexed search engine, 100,000-page scalability or an approved production capacity budget. There is no automatic linking, global cross-app index or new schedule.

Qualification separates a self-origin local browser fixture (actual app code, mobile UI, cursor pages and withholding a selection from the wrong parent), focused exact-origin/channel messaging tests, real staging HS sessions, and a genuinely deployed SHO launcher. A synthetic parent does not constitute real SHO deployment acceptance. An attempted HTTPS development mirror stalled before hydration and contributes no acceptance evidence. The later live paired launcher/identity and representative scale/fault/manual-device matrix remain open unless separately recorded. The gated HOLY-15 source ledger in this candidate still has no production task-creation adapter or exposed action.
