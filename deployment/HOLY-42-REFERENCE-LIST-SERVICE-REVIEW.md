# HOLY-42 durable configuration service — acceptance remains open

The internal model now has transactional persistence in migration033. No live permissions, tenant mappings, list data, routes or field bindings are seeded or registered.

Current native workspace membership and a reviewed workspace/tenant binding are mandatory, alongside the injected current suite tenant authority. Reading reference metadata needs an explicit tenant reference-list read grant. Configuration changes additionally require both explicit manage permission and current central tenant-administrator authority. Configuration grants never grant business-record or document access. No permission-management endpoint is added.

Changes require an actor/workspace-bound ten-minute preview with only definition/review hashes persisted, then an explicit operation ID and expected list version. Current schema/policy/data and suite-authority/permission revisions fence publication. The tenant transaction lock serializes competing operations. Identical retries return their applied version separately from the current definition; different input under the same operation ID fails. Current authority and configuration grants are rechecked before commit, and final database time fences review expiry. List publication, immutable version, operation, audit and tenant epoch changes commit or roll back together.

Versions preserve immutable actor/source/time/operation attribution. Managers can page configuration history; readers cannot use the manager history operation. Catalogue pages contain at most50 entries with actor/workspace/current-policy-bound five-minute cursors. Labels/translations are metadata, while stored values remain stable item IDs. New selections reject deprecated or ambiguous values. Removal/code reassignment remains conservatively blocked pending qualified dependency-aware removal.

Tests include actual PGlite transactions, stale/tampered/foreign reviews, current grant/membership denials, retry fences, immutable history, final-authority rollback, post-proof expiry rollback, catalogue cursor scope and label/deprecation semantics. Required real PostgreSQL CI exercises concurrent identical retries, competing versions and startup migration replay. Initial testing caught a collision with existing record-reference operation table; corrected to a dedicated `hs_data_reference_list_operations` registry. No released schema was changed to accommodate the collision.

Open full-story work: native list editor and actor-scoped recoverable inputs; multiple native field bindings and current permission-aware choices; filters/import code-or-ID mappings; complete dependency inventory and permitted unused-item removal; real suite tenant authority integration; full UI/API/concurrency/accessibility/device acceptance. Durable internal service evidence must not be reported as full HOLY-42 acceptance or a live feature release.
