# HOLY-16 scoped connected-client search foundation

`POST /api/v1/connected-search` accepts JSON `{query, workspaceId, spaceId?, cursor?, requestId}`. Query is 2–512 characters; identifiers are bounded; requestId is a UUID. POST keeps private queries out of ordinary URL logs. Cookie calls require exact HS origin. Bearer calls first pass the same trusted issuer/audience verification as all HS APIs; no caller-supplied user ID, wildcard CORS or service-wide reader is introduced. Response is no-store and includes requestId, results and nextCursor.

Matching/ranking reuse HOLY-2 searchPages and permission-filtered Repository reads. Workspace membership and optional space scope are validated. Each returned page is re-read for current permissions, metadata and query match. Cursor snapshots store only ordered page IDs and a query/scope hash; opaque 256-bit random cursor tokens are stored only as hashes and bound to actor/workspace/query/filter. Five-minute expiry is enforced by server clock. Pagination follows the original ID order, filters currently unavailable/nonmatching pages and returns at most 20. New matches require a new query; replay rechecks access and never returns copied old snippets. Expired snapshots/cursors can be removed by existing explicitly invoked bounded maintenance; no schedule is added.

The provisional bound is 1000 matching pages per snapshot and 60 requests per user per minute. Broad queries receive a refine-query error. Excess requests are counted in one per-user limiter row, with last bounded denied request ID, instead of creating unlimited audit rows. Other outcomes are correlated by request UUID, user and result count without raw query, title, path or snippets. The existing matching engine still scans authorised pages; this is not a qualified scalable index replacement.

Evidence: ten focused tests cover cursor stability, pool-independent persistence, replay, expiry, wrong actor/query/filter/workspace, tampering, current metadata/revocation/Trash, inactive membership, rate limits/accounting, bounded cleanup, exact browser-origin checks, payload bounds and no-store HTTP responses. Combined candidate: 197 local tests, ten real PostgreSQL tests, typecheck/build passed. PostgreSQL specifically verifies cursor survival across connection-pool restart and concurrent replay. Six real ClamAV checks passed on the preceding unchanged upload implementation; default integration skips are reported separately.

Remaining: actual SHO delegated-user adapter/session exchange, browser-client integration, approved rate/capacity/audit retention budgets, representative index/load/failure qualification and full BugOff execution. No integrated staging, production enablement or story Done is claimed. A separately configured actual identity service is still required; local preview is not identity qualification.
