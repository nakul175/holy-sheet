# Export one saved page deliberately

An authorised reader can review the current saved page and download a requester-bound PDF or UTF-8 Markdown copy. The export includes title and body, excludes comments/history/children/access grants, and warns that a delivered external copy cannot be recalled. A dirty local draft stays intact when the reader chooses the last saved version. Saving first remains an explicit alternative.

Jobs start only from the current expected version and verify its immutable revision digest. They are private to their requesting account and expire after 15 minutes by the server clock. A later edit cannot replace the snapshot. Ordinary read permission cannot export arbitrary history. Current page access, native workspace export policy, linked-page access/labels and job state are checked again after generation before response bytes are released. Permission or policy changes invalidate access; cancelling while generation runs prevents delivery. Retries keep the same job and reviewed digest. Audits record issuance of an authorised response, not proof that an operating system saved the file.

Readers may export by default. Only a native workspace administrator can change the versioned workspace policy. The policy UI uses current native membership and supports idempotent uncertain-request retries. Suite roles do not confer native administration. This change does not alter live memberships or page grants.

Markdown keeps portable headings, lists/checks, code, tables, links and Unicode. PDF uses embedded Roboto fonts, wrapping and repeating table headers; unsupported font characters are explicitly labelled with U+ placeholders and require acknowledgement. Markdown is offered for exact supported Unicode. Images/files are explicitly omitted with captions and acknowledgement; no private object URL or asset bytes are fetched. Restricted page references have neither title nor URL. This release does not claim packaged attachments, full script/font coverage, tagged PDF/PDF-UA, physical-device or manual screen-reader acceptance.

PDF generation runs in a separately bundled process with a 256 MB heap and 15-second limit. Import and PDF work share one per-process lease. The worker inherits no app secrets and allows only its bundled read path, no filesystem writes, addons, subprocesses or evaluated strings. Resource policies reject external URLs and local files. This is process isolation, not an OS network sandbox. The exact container also runs a synthetic renderer canary with networking disabled. Both output formats are capped at 25 MB; one export permits 500 distinct page references. Output bytes are not persisted on the server. Metadata expires through existing operator-invoked maintenance, without introducing a schedule.

Migration 018 is additive; rollback retains metadata tables and disables new routes with the old app. The main release excludes the separate page-organisation/Trash features awaiting their live admin fixture approval. This integration branch retains those gated features; it must not be promoted as a substitute. Shared editor package next50.11 identifies this integration candidate; the main release uses next50.10.

Qualification covers model permission/version/expiry/replay/cancellation/ref-integrity rules, HTTP origin/authentication and private response headers, UI uncertain responses/logout/draft preservation, real PostgreSQL competing operations, actual browser downloads and mobile WCAG checks. A five-page synthetic PDF includes wide tables, a multi-page long cell, code and final content: all pages are rendered, text bounds checked, and CI preserves both PDF and PNG evidence. Staging and production qualification is recorded separately; local/CI checks do not imply broad story acceptance.

Renderer API reference: [pdfmake server methods](https://pdfmake.github.io/docs/0.3/getting-started/server-side/methods/). The Node API uses its in-memory virtual filesystem for the embedded font container, with external resource access denied.
