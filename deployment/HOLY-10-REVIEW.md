# Recoverable page-tree Trash

Owners with explicit native workspace-management authority can review a page tree and move its active pages into one 30-day deletion batch. Already-trashed descendants keep their previous batch/deadline. Normal page, search, favourite, history, discussion and private-media authorization immediately excludes every newly trashed page. Content, block IDs, current version, history, comments, ownership and grant records remain stored.

Trash lists only recoverable batches whose root the current active member owns. Workspace administration is not a blanket recovery grant. Recovery checks current root ownership and destination-create/edit authority, shows current effective access and unavailable-file warnings, and restores only that batch. It never recreates a membership, role or grant from a deletion snapshot. An unavailable original parent requires choosing a current eligible location.

Delete/recover operations take the shared workspace lock, bind a tree-version/digest preview and deduplicate actor/root/batch-bound operation IDs. Expiry is enforced using the server clock at the recovery claim. A stale or failed operation changes no partial batch. Retried older acknowledgements report whether the page has since changed, rather than deleting or restoring it again.

Clean private media are retained throughout the recovery window. The existing manual cleanup path rechecks Trash retention, and a database guard also refuses an older application's attempt to purge recoverable ready/scanned media after rollback. Rejected/quarantined bytes remain removable immediately. No purge UI, permanent deletion, new maintenance schedule, credentials or provider permission change is introduced. Additive schema and data must remain on application rollback.

The UI preserves unconfirmed operation IDs, requires reviewed scope/access, and protects unsaved document/discussion drafts before leaving the current page. Trash is reachable from an empty workspace and the mobile workspace menu. Native management actions appear only after management authority is checked. Narrow-screen session controls remain below the mobile navigation rather than becoming obscured when editing scrolls.
