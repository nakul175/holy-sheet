# Structured record template foundation (HOLY-38)

Unexposed service, not full story completion. Templates belong to one tenant collection and require current collection view plus explicit manage-templates capability; no existing user receives that capability. Schema administration stays separately restricted. Catalogue names normalize Unicode, reject controls, have 1–100 code points and are case-insensitively unique. At most 200 templates per collection and fifty-item actor/scope/version-bound cursor pages are supported.

Named defaults have immutable revision history, optimistic saves and operation retry reconciliation. Current field read/write, type and reference/link rules apply when managing defaults. Empty templates can leave required creation inputs for the user. Unknown fields, ACL/schema instructions and unsupported document sections are rejected. Catalogue responses do not expose defaults; a template whose defaults cannot currently be read is unavailable without disclosing the hidden field or value. Exact normalized preview includes current schema defaults and validates ordinary creation, required same-tenant parent/legal parties, typed values, unique constraints and current permissions.

Ten-minute actor/workspace-bound previews retain only hashes/proof/version metadata, not submitted draft values. Instantiation rechecks current template/schema/policy/proof and native create/link/field rights. A fresh immutable record ID, native operation/event/outbox and source-template revision provenance commit together. Current schema defaults and explicit overrides are copied once; later template edits/deprecation never live-sync existing records. Completed retries return current permitted record state without a second creation. Identity, source version and provenance are immutable; no ACLs are copied. Native template operation channels are reserved from delegated API clients.

Active custom-field defaults register generic schema dependencies; core/typed record targets register internal source references so deletion cannot silently strand templates. Deprecating a template hides future choices and releases current configuration dependencies, while historical revision/origin evidence remains. No legal hold or audit purge schedule is invented.

Tests cover explicit capabilities, names/version/retry, exact normalization, fresh IDs/no grants, source provenance, template edit/deprecation isolation, current field/reference/create rights, schema dependency and deletion impact, stale/expired previews and final-proof rollback. Required CI adds actual PostgreSQL simultaneous instantiate retry and all existing regression/accessibility/container/backup-restore gates.

Remaining full HOLY-38 work: native catalogue/editor/phone/keyboard UI, approved live tenant/capability mapping, document-section template composition and qualification with real connected reference adapters. Those unsupported capabilities are rejected rather than silently ignored. No live catalogue/defaults or grants are seeded.
