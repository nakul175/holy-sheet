# HOLY-3 confidential sign-in bridge checkpoint

New routes: GET `/auth/sign-in`, GET `/auth/callback`, POST `/auth/sign-out`, GET `/auth/signed-out`, GET `/auth/session`. The bridge is disabled by default with `HS_OIDC_ENABLED=0`, independently of the disabled document-editor flag. No accounts client, secret, account binding or bootstrap membership is created by this code.

The pinned official openid-client 6.8.8 library handles confidential authorization-code exchange with client_secret_basic, S256 PKCE, expected state/nonce, exact issuer/audience and cryptographic ID-token signature verification. Discovery must advertise S256 and expected same-issuer HTTPS endpoints/JWKS. Random browser transactions are AES-GCM encrypted using a distinct configured 32-byte key, purpose-bound, HttpOnly/Secure/Host-prefixed and expire in five minutes. Return destinations are restricted to local page/embed paths. Redirects never derive from an incoming Host header. Refresh/offline tokens are not requested or retained; tokens and provider error bodies are not logged or returned as JSON.

Successful login issues short-lived HttpOnly/Secure/SameSite=Lax `hs_session` and `__Host-hs_session` cookies bounded by the verified ID token. Enabling the bridge requires the protected companion; duplicate/conflicting cookies fail closed. Bearer delegation remains independently verified. The successful callback is a standalone no-store HTML document with nonce-bound script: an anonymous storage marker locks other same-origin HS tabs before replacing the callback URL with the allowlisted destination. No token reaches JavaScript or that HTML body. Native app grants remain separate from suite identity.

Local sign-out requires exact Origin, clears both session cookies, and uses a browser-bound state for the registered suite logout return. The UI checkpoints the initiating draft first. Cross-tab logout/account changes unmount decrypted content; other tabs receive a best-effort checkpoint signal before locking. Verified document identity seeds the account guard. Session checks on focus/visibility and once per minute detect expiration/account change, while transient network/503 failures preserve existing offline editing. Recovery is promised only through the last completed encrypted checkpoint. Initial page errors offer sign-in only for authentication failures, not ordinary 404s. Embedded sign-in opens a standalone window.

Validation: 365 local tests, typecheck and production build passed. Thirty-four new cases cover the actual OIDC library against an isolated HTTPS-protocol fixture with real RSA signatures; PKCE/client authentication; state/nonce/signature/issuer/audience/lifetime/replay/cookie/metadata boundaries; actual HS JWT verification; session-route privacy; cross-tab unmount/checkpoint; account change; offline behavior; and protected-cookie selection. The existing three JWT cases also passed in the focused identity run (37 total). The default run skips sixteen opt-in service cases; exact-revision CI supplies its separate PostgreSQL evidence. These are not a live accounts login or executed BugOff cases.

Registration required before enabling: confidential client ID `holy-sheet`; exact `https://staging.holysheet.aplyd.org/auth/callback` and post-logout `https://staging.holysheet.aplyd.org/auth/signed-out`; code + S256; client_secret_basic; RS256 ID tokens; scopes openid/email/profile/aplyd. Supply private `HS_OIDC_CLIENT_SECRET` and separate Base64 `HS_OIDC_TRANSACTION_KEY`, keep editor/preview off, then perform a real authenticated browser rehearsal. Confirm the provider supports the client_id/post_logout_redirect_uri logout request without an ID-token hint before rollout.

**Open suite-logout gate:** public accounts discovery does not advertise front-channel/back-channel logout or introspection. This code implements local/RP-initiated logout and expiry/account-change detection, not immediate notification when another suite app ends the central session. Provider contract, implementation and live evidence are still needed. App entitlement/revocation policy, bootstrap binding, actual SHO embedding/logout, mobile/screen-reader and full BugOff qualification remain open. No HOLY-3 acceptance/Done claim.
