# Personal navigation retries and live backlinks

A document open whose Recents write fails now offers an explicit retry for that currently open page. Refreshing the personal list continues to be read-only; it no longer promises to retry the failed write. Errors and late responses are scoped to the current page/account and disappear on navigation or logout. Successful opens, current-permission filtering, the 50-unique-page cap, versioned favourite ordering and independent clear semantics remain in the existing server transaction.

An open Backlinks dialog checks current saved references every four seconds while visible and immediately when its tab becomes visible. It refreshes the current cursor rather than jumping to the first page, avoids overlapping background reads and ignores late responses after closing/logout. Any failed authorization/service read clears previously displayed metadata and offers a fresh read. No polling or timers run for a closed dialog. Linking still grants no access and only durable source saves change the index.

Focused coverage includes failed-write recovery, navigation/logout races, external reference refresh, pagination, denied reads, slow requests and hidden tabs. Browser qualification exercises a dropped Recents write at phone width and external source save/removal while the target dialog stays open; broader browser accessibility and server/PostgreSQL tests run in CI. Local browser evidence is not physical-device or manual screen-reader acceptance. The shared HS/SHO state continues to use the same account-authorized API; a full independent SHO user/device acceptance matrix remains separate.

This release has no migrations, identity grants, credentials, schedules, private-file changes or new deployment infrastructure. App-only rollback to the prior qualified image is compatible. HOLY-9/10 page-tree operations are deliberately absent from this main-based candidate pending their live administrator-fixture approval, while their code remains on the requested integration branch.
