# Permission-aware saved views (HOLY-23)

The service foundation is unchanged: private views stay owner-bound even against shared-view managers. Shared workspace views require the separate `manage-views` capability; it grants no record edit or schema permission. IDs, tenant/workspace, owner and audience remain immutable; publishing a private view requires an explicit new copy rather than changing its audience. Versioned saves preserve caller drafts on conflict, deduplicate actor-bound operations and audit IDs/version only. Deleting a view removes its schema dependencies and leaves all records/history untouched.

Native routes now call that service through the same suite-tenant authority as records, permissions and schema (`HS_RECORDS_ENABLED` plus the current suite tenant proof; no JWT-role fallback). `GET/POST /record-views` lists, saves and deletes. `GET /record-views/:viewId` runs the saved table with the opaque cursor. The records screen can create and run a personal view, and a caller with `manage-views` can save or publish a shared copy. Restricted columns are omitted; a restricted filter or sort stays a generic unavailable configuration and is not executed.

Definitions use stable field-ID columns, up to twelve AND filters, up to three sorts and explicit archived inclusion. Supported typed filters include exact values, literal text prefix/contains, numeric/date comparison, select membership, multi-select/reference inclusion and emptiness. Currency and complex-value comparisons, OR/nested predicates, computed fields and complex-value/long-text sorting remain unsupported and are rejected. The compiler validates all field identities, operators, casts and directions; values and JSON keys are SQL parameters. Restricted columns are removed from response fields/values. A restricted filter/sort returns a generic unavailable configuration and blocks execution; hidden columns never confer access.

Queries recheck current record/field permissions on the server, exclude Trash, and return fifty rows through stable multi-column keysets with nulls last and an ID tie-break. Five-minute opaque cursors bind exact actor, tenant, workspace, view definition/version and schema/policy/data revisions. A changed dataset requires restarting rather than pretending to offer a stable snapshot. View metadata is bounded to 200 per workspace collection. Synthetic tests exercise nulls, ties, literal wildcards, typed predicates, stale cursors, current row grants and restricted-field probing. Name-prefix scale evidence from the foundation is not a performance claim for arbitrary JSON filters/sorts.

Saved custom-field references register dependencies with generic private/shared labels: schema administrators see necessary impact without private view titles. The native table is the records screen, not a separate board, calendar, keyboard grid or mobile editor. Archive, trash, merge, import, export and history restore stay out of this surface. Suite tenant mapping is still the existing `HS_RECORDS_ENABLED` proof used by records, permissions and schema; this story does not add a tenant-provisioning adapter or a JWT-role fallback. Representative query indexing, a fuller dependency inventory and live role matrices remain open.
