# Delegated record client contract foundation (HOLY-29)

Unexposed version-one service contract. No HTTP route, OIDC client/delegation registration, tenant mapping, live reference source or cache is activated. A required current client-authority adapter verifies registered app, initiating user, tenant, workspace, permitted operations, stable delegation revision and expiry. Native suite tenant authority/membership and record/field permissions remain separately mandatory. Service calls preserve initiating user and distinct service subject. Reserved native/import channels cannot be impersonated by a delegated client. No token claims or browser-provided app/tenant IDs substitute for either authority.

Typed commands expose permitted query/detail/create/update/protected history, connected references and change polling. Native immutable IDs, version conflicts and idempotency apply. Operation identities are fenced by trusted source app and import batch so another app/channel cannot claim a successful write. Native mutation, protected history, metadata outbox and final client-authority recheck share one SQL transaction; a changed delegation rolls back the complete operation. Credential handles are never serialized, logged or stored in operations. Responses specify private/no-store and online-only authority; a future HTTP adapter must actually set those headers and implement its reviewed token, origin/CSRF, rate-limit and discovery contract.

Connected references require a separately qualified current owning-source adapter before and after SQL mutation. Source app comes only from verified delegation; source type/ID cannot be arbitrary URLs. Registration/removal use native record link permission, active state and expected version. Tenant/record locking fences Trash/merge; changes make a new metadata version and outbox event. Only the owning app/source tuple can be removed. Retries return current registration state, including later removal. No connected-app database or authoritative business field is duplicated. Live distributed failure/reconciliation and all-client alias support remain integration gates.

The immutable transactional outbox contains tenant/record/version/operation/app/actor/service/kind/time metadata, never names/field values. Stable sequence cursors partition by actor/workspace/tenant/client/delegation/schema/policy/suite revision and expire in five minutes. Polling scans at most 500 events to return at most 50 currently readable records; hidden IDs/counts are not returned. Retries may redeliver stable event IDs: clients must deduplicate by ID and retain the returned cursor, never treat offline caches as authoritative. Delivery is at least once, not exactly once or a running dispatcher. Native tenant serialization is required for cursor ordering; direct client DB writes are unsupported. Outbox/history are retained independently of Trash; no purge or scheduler is enabled.

Tests cover every identity boundary, operation privilege separation, native retry/source conflicts, service-vs-user provenance, delegation/source revocation rollback, immutable references, Trash races, safe events and actor/app cursor isolation. Required CI includes actual PostgreSQL reference/Trash concurrency and existing full regression/accessibility/container/backup-restore gates.

Still open for full HOLY-29: deployable authentication/delegation HTTP adapter, full lifecycle/import/export/schema API surface, real source adapters and cross-app fault/reconciliation acceptance, cache permission-invalidation contract, published client SDK/consumer adoption, approved suite mappings and representative throughput. No full completion or live integration is claimed.
