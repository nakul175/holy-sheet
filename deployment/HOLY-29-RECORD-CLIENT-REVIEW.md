# Delegated record client contract foundation (HOLY-29)

## Foundation already in the tree

The version-one service contract, connected-reference registration, metadata outbox, sequence cursors and service tests were already present (`SharedRecordApiV1`, `db/028_shared_record_clients.sql`). That foundation remains the authority for the behaviour below. This connection does not add an OIDC client or delegation registration, a tenant-provisioning adapter, a JWT-role fallback, a live owning-source adapter, a running dispatcher or a purge.

A required current client-authority adapter verifies registered app, initiating user, tenant, workspace, permitted operations, stable delegation revision and expiry. Native suite tenant authority/membership and record/field permissions remain separately mandatory. Service calls preserve initiating user and distinct service subject. Reserved native/import channels cannot be impersonated by a delegated client. No token claims or browser-provided app/tenant IDs substitute for either authority.

Typed commands expose permitted query/detail/create/update/protected history, connected references and change polling. Native immutable IDs, version conflicts and idempotency apply. Operation identities are fenced by trusted source app and import batch so another app/channel cannot claim a successful write. Native mutation, protected history, metadata outbox and final client-authority recheck share one SQL transaction; a changed delegation rolls back the complete operation. Credential handles are never serialized, logged or stored in operations. Responses specify private/no-store and online-only authority.

Connected references require a separately qualified current owning-source adapter before and after SQL mutation. Source app comes only from verified delegation; source type/ID cannot be arbitrary URLs. Registration/removal use native record link permission, active state and expected version. Tenant/record locking fences Trash/merge; changes make a new metadata version and outbox event. Only the owning app/source tuple can be removed. Retries return current registration state, including later removal. No connected-app database or authoritative business field is duplicated. Live distributed failure/reconciliation and all-client alias support remain integration gates.

The immutable transactional outbox contains tenant/record/version/operation/app/actor/service/kind/time metadata, never names/field values. Stable sequence cursors partition by actor/workspace/tenant/client/delegation/schema/policy/suite revision and expire in five minutes. Polling scans at most 500 events to return at most 50 currently readable records; hidden IDs/counts are not returned. Retries may redeliver stable event IDs: clients must deduplicate by ID and retain the returned cursor, never treat offline caches as authoritative. Delivery is at least once, not exactly once or a running dispatcher. Native tenant serialization is required for cursor ordering; direct client DB writes are unsupported. Outbox/history are retained independently of Trash; no purge or scheduler is enabled.

Service tests cover every identity boundary, operation privilege separation, native retry/source conflicts, service-vs-user provenance, delegation/source revocation rollback, immutable references, Trash races, safe events and actor/app cursor isolation. Required CI includes actual PostgreSQL reference/Trash concurrency and existing full regression/accessibility/container/backup-restore gates.

## Connected in this change

`POST /api/v1/workspaces/:id/tenants/:tenantId/record-client` submits one version-one command (`apiVersion`, `operation`, `payload`) through the same suite-tenant authority as records, permissions, schema, saved views, lifecycle, merge, import, export and history (`authenticateRecordAuthority` and `HS_RECORDS_ENABLED`). There is no JWT-role fallback and no tenant-provisioning adapter. Each request constructs `SharedRecordApiV1` with that verified authority and `unavailableRecordClientAuthority`. No `RecordReferenceSourceAuthority`, value authority or `HistoricalReferenceAuthority` is supplied.

The production client authority does not inspect token claims, the Authorization header, or app, tenant, workspace or operation ids supplied by the browser. It fails closed with `record_client_denied`. Reference registration still fails closed with `record_source_unavailable` when no owning-source adapter is configured. Protected history still omits nonempty record and attachment values without a historical reference adapter.

The route passes the authenticated actor and the workspace and tenant from the URL. It does not copy the bearer token into the command context. A response is published only when the service result is exactly version one, `cacheControl` is `private, no-store`, and `offline` is false, with no extra top-level fields. The HTTP response sets `Cache-Control: private, no-store` and `Vary: Cookie, Authorization`. Same-origin is required, as on the other record mutations. Token exchange, client registration, discovery, non-browser CSRF and rate limits are not implemented on this route.

The command names the service already accepts are `records.query`, `records.get`, `records.create`, `records.update`, `records.history`, `references.register`, `references.remove` and `changes.poll`.
