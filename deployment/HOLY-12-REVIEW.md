# HOLY-12 references and backlinks foundation

Same-workspace page selection uses existing page-read permission. Ordinary document saves validate newly inserted or retargeted stable references before committing. Unchanged references to now-unavailable pages can remain as safe placeholders so unrelated edits are not blocked. Labels resolve the current authorised title within source workspace; they are not copied into saved content. Plain URL links remain supported independently.

Backlinks use a partial expression index on canonical current hs_blocks. Index visibility is part of the save transaction, with no queue or stale title cache. Retrieval requires current target access and filters sources by current active membership, access, workspace and deletion state. One entry per source carries occurrence count. Stable ID keyset pagination returns 20 entries without inaccessible totals. The dialog clears results during loading/error, refreshes on focus/open and logout, supports source opening and has explicit refresh/pagination controls. Ordinary click on a reference navigates even from an editable atom; native before-unload recovery guards remain active.

The batched permitted-page traversal in backlinks and personal navigation now matches the canonical reader's 100-node inheritance boundary. A regression fixture grants then revokes direct access on a descendant 100 edges deep and verifies neither list reveals the otherwise unavailable page. No sharing grant or notification is created by linking or reading backlinks.

Evidence: seven focused reference tests plus seven personal-navigation tests passed. Combined: 187 local tests, nine real PostgreSQL integration tests, typecheck and production build passed. Real PostgreSQL coverage verifies saved occurrence counts, rejected-operation rollback and reference removal. Browser rehearsal inserted/saved a same-workspace link, resolved its current title after reload, followed it, and displayed the saved source with one occurrence. Remaining gates: browser/mobile/accessibility and representative large-list qualification; source-title/path rename/move integration with HOLY-9; actual suite identity/SHO staging; explicit reference policy across every template/import/history transfer path. The existing direct template/history writers do not yet use the new ordinary-save reference validator, so AC6 is not fully qualified. Large lists use next-page and first-page refresh controls, without a previous-page stack. Existing visible metadata refreshes on focus/read, without push revocation events. Production remains disabled; no story Done or integrated acceptance is claimed.
