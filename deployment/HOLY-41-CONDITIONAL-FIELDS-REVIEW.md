# Typed conditional field policy foundation (HOLY-41)

No live rules, tenant mappings, client draft authority or permission grants are seeded. Current verified tenant administrator plus collection schema/view permission manages policy; current read permission for every source/target field is required. Rule messages expose no predicate values, private field labels or private draft contents.

At most twenty distinct target rules use five-clause all/any groups with typed equality, empty/nonempty, number/date ranges and multi-select containment. Unknown/deprecated fields, unsupported reference-source predicates, type coercion, cycles/self-dependencies, oversized values and ambiguous show/required combinations are rejected. Static required fields cannot be hidden. When a field is both shown and required conditionally, the same condition must govern both. This is bounded typed logic, not arbitrary expressions or a formula engine.

The shared native value validator enforces conditional requirements for ordinary creates/updates, delegated API writes, staged imports, templates and value/history/lifecycle restoration paths that use kernel validation. Unreadable rule fields deny uniformly before evaluation; static hidden required labels also get generic denial. Hiding never clears values; an explicit permitted edit is required to clear them. Current condition-state projection supplies visibility/required metadata without predicate values. The renderer consumes that metadata, announces retained hidden values and preserves controlled form drafts. The records screen and typed rule screen use that contract; see Connected in this change.

Policy review checks up to 5,000 existing unmerged records, including recoverable Trash. Without current restore capability a recoverable-Trash review is blocked without inspecting its values, preventing a new policy from stranding recovery data or leaking it. Invalid existing records block publication without rewriting them. Larger datasets require a separately qualified bounded migration. Current field dependencies block incompatible schema changes; conditional-required fields must be in a published editable layout, and later layouts cannot hide them.

Pending previews retain hashes/version/proof metadata for ten minutes. Publication rechecks record data revision, schema/policy/current policy version and suite proof, advances schema/policy epochs, and commits immutable policy history, operation retry ledger and metadata audit atomically. Current active import drafts uniformly block policy changes regardless of their content. A complete qualified connected-draft quiescence authority is mandatory, with revision recheck at commit; no private draft-value oracle is used. Old form/import version tokens require review on resume. The production draft-epoch adapter wired by the route fails closed and does not claim that inventory. No dispatcher or schedule exists; all writers and epoch/fault handling must be qualified before activation, including compatibility of any rollback writer.

Tests cover native/API/import enforcement, typed comparisons without coercion, cycles, retained hidden values, current permission privacy, old records/Trash, private-draft/quiescence gates, stale reviews, draft-authority rollback, operation retries, schema/layout dependencies, final-proof expiry and actual PostgreSQL policy-vs-record creation races. Browser tests at desktop/phone verify conditional hide/show retains an edited controlled value, displays handling guidance and keeps WCAG checks green.

## Connected in this change

`GET/POST /api/v1/workspaces/:id/tenants/:tenantId/record-conditions` calls `SharedRecordConditionRepository` through the same suite-tenant authority as records, permissions, schema, saved views, lifecycle, merge, import, export, history, the record client, custom collections and record layouts (`authenticateRecordAuthority` and `HS_RECORDS_ENABLED`). There is no JWT-role fallback and no tenant-provisioning adapter. Each request constructs the repository with the verified authority and `failClosedConditionalDraftEpoch()`. That production draft-epoch adapter does not read draft values and does not report a qualified connected-writer inventory, so publication stays blocked with `record_condition_drafts_unavailable`.

`GET ?collection=` reads the management policy for a current tenant administrator with collection schema and view. `GET ?projection=state` and `POST kind: state` return visibility, required and retained-hidden metadata for a record or the caller's own draft values. Predicate values, private labels and policy rules are not part of that projection. Any other query, a forged field, a cross-origin write, a missing feature flag or an unexpected failure is rejected. Responses are `no-store` and vary on cookie and authorization.

`POST kind: preview` and `kind: publish` keep the ten-minute review, exact selection and `confirm: publish-conditional-policy`. The transport kind is not passed into publication. The typed rule screen builds all/any groups of up to five comparisons and does not offer an expression box. Static required fields cannot be marked hidden there. The records screen asks for the projection when a published layout is open, and again when a fallback draft contains field values. It passes that metadata to the layout renderer and leaves hidden draft values in place when it saves.

Remaining full story: a qualified connected-draft inventory that can report quiescence, real multi-client fault/recovery, and representative throughput/device acceptance beyond the existing renderer checks. No full HOLY-41 completion is claimed.
