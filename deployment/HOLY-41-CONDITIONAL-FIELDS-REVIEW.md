# Typed conditional field policy foundation (HOLY-41)

Unexposed native policy service. No live rules, tenant mappings, client draft authority or permission grants are seeded. Current verified tenant administrator plus collection schema/view permission manages policy; current read permission for every source/target field is required. Rule messages expose no predicate values, private field labels or private draft contents.

At most twenty distinct target rules use five-clause all/any groups with typed equality, empty/nonempty, number/date ranges and multi-select containment. Unknown/deprecated fields, unsupported reference-source predicates, type coercion, cycles/self-dependencies, oversized values and ambiguous show/required combinations are rejected. Static required fields cannot be hidden. When a field is both shown and required conditionally, the same condition must govern both. This is bounded typed logic, not arbitrary expressions or a formula engine.

The shared native value validator enforces conditional requirements for ordinary creates/updates, delegated API writes, staged imports, templates and value/history/lifecycle restoration paths that use kernel validation. Unreadable rule fields deny uniformly before evaluation; static hidden required labels also get generic denial. Hiding never clears values; an explicit permitted edit is required to clear them. Current condition-state projection supplies visibility/required metadata without predicate values. The renderer consumes that metadata, announces retained hidden values and preserves controlled form drafts; actual full record-form and rule-builder integration remains open.

Policy review checks up to 5,000 existing unmerged records, including recoverable Trash. Without current restore capability a recoverable-Trash review is blocked without inspecting its values, preventing a new policy from stranding recovery data or leaking it. Invalid existing records block publication without rewriting them. Larger datasets require a separately qualified bounded migration. Current field dependencies block incompatible schema changes; conditional-required fields must be in a published editable layout, and later layouts cannot hide them.

Pending previews retain hashes/version/proof metadata for ten minutes. Publication rechecks record data revision, schema/policy/current policy version and suite proof, advances schema/policy epochs, and commits immutable policy history, operation retry ledger and metadata audit atomically. Current active import drafts uniformly block policy changes regardless of their content. A complete qualified connected-draft quiescence authority is mandatory, with revision recheck at commit; no private draft-value oracle is used. Old form/import version tokens require review on resume. No production authority adapter, dispatcher or schedule exists; all writers and epoch/fault handling must be qualified before activation, including compatibility of any rollback writer.

Tests cover native/API/import enforcement, typed comparisons without coercion, cycles, retained hidden values, current permission privacy, old records/Trash, private-draft/quiescence gates, stale reviews, draft-authority rollback, operation retries, schema/layout dependencies, final-proof expiry and actual PostgreSQL policy-vs-record creation races. Browser tests at desktop/phone verify conditional hide/show retains an edited controlled value, displays handling guidance and keeps WCAG checks green.

Remaining full story: native typed rule builder and full record-form host, production suite/draft-epoch adapters, real multi-client fault/recovery and representative throughput/device acceptance. No full HOLY-41 completion is claimed.
