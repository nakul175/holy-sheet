# Custom-field schema review foundation (HOLY-22)

This extends the unexposed shared-record service; no HTTP/UI factory, live suite-tenant adapter, tenant provisioning or grants are introduced. A current trusted tenant administrator **and** explicit collection schema capability are both required. Native workspace administration, JWT roles and email are insufficient. Current suite authority is rechecked at commit, including revision and administrator status.

Custom fields have UUID identities independent of labels, thirteen validated types, at most 100 fields per collection and 100 distinct select choices. Built-in identity/tenant/parent rules cannot be edited. A ten-minute actor/workspace/tenant-bound preview exposes definition changes, aggregate validation counts and registered view/import/integration dependency impacts. Defaults apply only to future creates; no implicit backfill occurs. Schema, data, dependency, policy and suite-authority revisions bind the review. Apply rejects stale or expired reviews and uses an actor-bound operation ledger, immutable versioned schema definitions and metadata-only audit records.

Populated type conversions, removed populated choices, unresolved required fields, duplicate values and incompatible changes with active dependencies are blocked. Sensitivity can be raised immediately but cannot be lowered in this workflow. Schema permission grants no field-value read/write/history permission. Deprecated fields remain readable under current field rights, cannot be edited, and do not apply defaults or required rules to new records. Physical deletion is not provided. Enabling uniqueness backfills at most 5,000 populated values atomically; a larger existing dataset needs a separately qualified bounded migration. Label-only edits retain the existing uniqueness registry.

Record changes advance tenant data revision once per statement using PostgreSQL transition tables, including bulk SQL fixtures, so preview validity does not rely on stale counts. Dependencies likewise advance their revision. Registered dependencies are synthetic fixtures here: a complete real view/import/integration/reference-policy inventory adapter and native review UI remain deployment gates. No live record/schema features are enabled or full HOLY-22 completion claimed.

Validation includes stale-data/schema/dependency review rejection; capability and administrator revocation; sensitive historical values; required/unique backfill; stable rename/default semantics; deprecated read/write behavior; limits; identity/history database guards; and existing typed-record regressions. Required full CI and real-service gates are recorded with the PR.
