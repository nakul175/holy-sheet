## Implemented boundary

The existing page Owner explicitly enables a reviewer list from already permitted page editors. Configuration does not add membership or grants. Readers then see only an active immutable publication; no publication means the configured page is unavailable to readers. Editors keep the current draft and can inspect the independent published snapshot. An independent current reviewer, excluding both submitter and source author, approves or rejects an exact revision with a reason. The current Owner publishes approved snapshots or withdraws them. Versioned commands, scoped retry records, workspace/page locks and minimal metadata audit make retries and stale/concurrent requests explicit.

Submission captures validated title/body, attachment digests and a reference manifest. Plain page references pin a visible label and exact source revision. The optional bounded `submit.bindings` contract maps an existing page-link block ID to a source block ID on that same linked page; supported paragraph/heading/code blocks resolve into an immutable reviewed body. It adds no live-block or snippet authoring/catalogue. Unknown nodes, missing/unsupported source blocks, changed source/asset digests and inaccessible/cross-workspace sources fail safely. Publication-time resolution repeats the review check. Current source permissions still redact pinned content at every read/export. The current source revision is never substituted into published content.

The page/document API, list/search, personal navigation, reference labels, backlinks, export preparation/delivery and media gateway enforce draft isolation. Publication fingerprints refresh open reader surfaces after withdrawal, supersession or reference redaction. Media delivery rechecks current publication visibility after object retrieval and checks the full digest before returning bytes, including ranges. Published exports are bound to publication identity; previously prepared draft exports are invalidated when publishing is enabled. An exported or screenshotted copy cannot be recalled.

Migration `063_document_publishing.sql` is additive and replayable. It provisions no workflow, user or grant. Reviews and publications retain their own immutable body/manifest rather than depending on expiring ordinary revisions. Pending/approved review attachment pins remain while the source page is live; rejected proposals cease to pin assets, while ordinary history/recovery rules still apply. No automatic publication purge is introduced. Snapshot retention policy and capacity must be accepted before release.
