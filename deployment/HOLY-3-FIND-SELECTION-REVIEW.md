# HOLY-3 find selection checkpoint

Whole-file/image/reference matches use node selections rather than invalid text ranges at block boundaries. Find captures selection bookmarks, maps them through document changes and preserves node identity/direction. If a whole-document refresh invalidates positional mapping, unchanged stable text anchors/quotes provide a conservative fallback. Deleted or changed targets are refused instead of guessing a replacement. Find navigation/restoration creates no document or Undo operation.

Read-only content has an explicit keyboard focus target/indicator. Cmd/Ctrl+F is handled in the read-only DOM path as well as editable content; modified/composition/AltGraph combinations are preserved. Escape from the find bar closes find without dismissing an enclosing dialog and returns focus to the document, including history previews. File metadata displays loading while authorization/name lookup is pending; state is bound to attachment identity, and prior names are cleared during revalidation.

Evidence: nine new selection/shortcut/editor cases, thirteen focused find cases including existing label/Unicode coverage, 379 combined local tests, typecheck and production build passed. Tests cover node/text selections, edit mapping, reverse direction, deletion, whole-document refresh including a last-block regression, invalid ranges, read-only focus and shortcut boundaries. Native browser filename find selected clean-one as a whole node, then restored the original clean-two node selection. In a read-only history preview, Cmd+F opened HS find; Escape preserved History and returned focus to the preview. Saved source version18 and its document hash remained unchanged across the recorded history rehearsal. Both synthetic protected files still returned200 with the previously recorded byte hashes.
