# Verified tenant authority client — not activated

The HS server now has `authenticateRecordAuthority(request)`, a factory for the required current-tenant authority used by native record repositories. It authenticates the existing suite token, issuer, audience, expiry and current upstream session before capturing the signed session UID. The public Actor stays `{id}`; the UID and confidential client secret live in a closure and are never properties returned to callers or added to existing API output.

The factory requires explicit `HS_RECORDS_ENABLED=1` and real suite-session mode. Local page preview continues working but cannot establish record tenant authority. No email, global role, workspace-admin or fallback synthetic mapping is used. The client calls the prepared Accounts `/internal/tenant/status` contract by authenticated POST with no redirects or result caching, a three-second timeout, bounded request fields and strict response validation. Subject, tenant and workspace must all match. Unavailable/malformed authority returns503, inactive authority returns restricted404, and a changed authority returns409. Raw provider errors or credentials are not surfaced.

Existing repository operations obtain a fresh proof before and after their native transaction and independently require active HS workspace membership, reviewed tenant binding and native capabilities. The client does not create any of those grants. A synthetic signed-token test exercises the HTTP client and a real native record transaction together; a changed final revision rolls back record/event state. This is local protocol/SQL evidence, not live Accounts or PostgreSQL qualification.

No record HTTP route, native UI, live flag, mapping, tenant administrator or deployment is introduced by this batch. The prepared central adapter must be reviewed and qualified separately; this client does not claim that endpoint currently exists on staging. Individual story acceptance remains open.
