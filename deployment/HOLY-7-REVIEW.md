# HOLY-7 implementation checkpoint

This is an incremental foundation behind the existing production access flag. It is not a declaration that HOLY-7 is Done.

Implemented: immutable attributed revisions for new durable saves; no-op saves remain revision-free; newest-first pagination; editor/owner-only list, preview, compare and restore; current authorization on every request; 90-day availability measured from supersession; rich read-only preview and labelled block comparisons; explicitly reviewed ten-minute restore previews; optimistic live-version checks; atomic append-only restore; actor-bound idempotent retries; minimal audit records; preservation of ACL, location, child pages and discussions. Available history protects file retention. Unavailable/quarantined files become reviewed placeholders, and attachment state or identity changes require refreshed review. Viewers cannot retrieve historical attachment bytes. The user's own local crash-draft text remains governed by the separate HOLY-3 recovery policy.

The UI does not replace unsaved document changes with an external restore: clean sessions accept the new version, while a draft or in-flight save opens the existing conflict review. Dirty documents cannot initiate restore. Restored content crosses the editor's remote history boundary so prior session Undo cannot replay an old whole-document inverse.

Existing snapshots retain honest legacy/unknown-author labels and a warning that their original integrity hash was not recorded. They receive structural validation; this does not retroactively prove their original integrity. This legacy compatibility decision needs acceptance before release.

Validation includes permission denial for Viewers/Commenters, pagination, immutable SQL revisions, stale review rejection, revoked access, expired previews, future schema rejection, retention boundaries, digest mismatch, historical media protection, attachment availability changes, cancelled upload completion, and rejected-object purge/retry. Real PostgreSQL tests cover concurrent restore retry deduplication and immutable revision enforcement alongside the existing concurrency suite. Full logs are local ignored artifacts.

Remaining release gates: actual suite identity and SHO host integration, both-host synchronization qualification, representative performance budgets and measurements, complete keyboard/screen-reader/mobile coverage, security review of legacy compatibility and file/recovery policy, and explicit BugOff case execution. Comparison currently labels whole top-level block additions/removals/moves/content-or-format changes with before/after text and rich snapshots; fine-grained inline diff remains a potential usability refinement. No acceptance case is marked passed solely because a unit test passes.
