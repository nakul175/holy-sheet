# Import a document into one new private page

A user can select one Word (.docx), Markdown (.md) or UTF-8 text (.txt) file, explicitly name its new page and choose a currently accessible HS space. Conversion returns a private read-only rich preview and a report before anything creates a page. The user reviews content, title, destination and warnings, explicitly accepts image omission when applicable, and commits one independent private page. Existing pages are never overwritten. Supported text/headings/styles/lists/task state/code/tables keep their order; block IDs are fresh. Source ownership, permissions, comments, history and suite bindings are not copied.

Source inputs are bounded at 20 MiB, 100 MiB expanded, 5,000 ZIP entries and 10,000 rich blocks. Existing HS document depth/table/25 MB limits also apply; incompatible content fails explicitly without truncating or partially creating a page. Encrypted or corrupt archives, unsafe paths/duplicates, invalid entry sizes/checksums, macros/active embedded objects, XML DTD/entities and unsupported types fail before preview. Text is UTF-8. Unsupported Word layout, lower-level headings, merged cells and unsafe/relative links produce warnings or readable conversions.

Parsing runs in a separately bundled child process with a 256 MB heap and 15-second deadline, one concurrent parser per application process, no inherited application secrets, filesystem writes, addon/child-process permissions or evaluated strings. This is process/resource isolation, not an OS network sandbox. The parser uses inert HTML nodes and an explicit rich-node/URL allowlist; source HTML is never rendered or executed. Word external-file access is explicitly off. Markdown HTML remains literal text. Images are never fetched, stored or served: placeholders/report counts require explicit omission confirmation. No private-object policy or scanner bypass is introduced.

Raw source bytes are never saved to disk, a database upload or logs. Metadata travels in a bounded header, not URL query strings. The converted preview is private to its author and current native workspace membership, expires by the server clock in 24 hours, and is cleared on commit/cancel or by the existing operator-invoked lifecycle after expiry. No maintenance schedule is created. Audit records contain only safe job/file/destination/result/count metadata, not source or converted body text.

Preview and commit recheck the current destination rule already used by HS page creation: active native workspace membership. Nothing promotes a suite claim or changes users/grants. Commits take the workspace lock, bind the reviewed digest, deduplicate the job and atomically write page/document/history/audit/result. A retry checks current page access and returns the same page. Concurrent cancel versus commit has one terminal outcome. Unconfirmed UI requests retain their exact intent, lock changed fields and offer the same retry. Closing/navigation protects entered fields; success presents an explicit saved result before opening it. Logout removes private preview state and ignores late responses.

The additive migration is 017 so it does not collide with page-organisation/Trash migrations retained only on the integration branch. Application rollback retains the new table; an older application does not expose the import endpoint. The main-based candidate excludes those separate live-admin-gated features. Editor package next50.8 identifies this candidate, separately from integration next50.7.

Qualification includes conversion/security and role/expiry/replay/cancel transaction cases, HTTP boundaries, real PostgreSQL concurrent preview/commit/cancel and dump/restore, actual Word and Markdown browser workflows, mobile omitted-image review, a deliberately lost successful commit response, existing-document preservation and WCAG/keyboard regressions. Live staging and production are qualified separately before promotion; local/CI evidence is not physical-device or manual screen-reader acceptance.

Parser references: [Mammoth security](https://github.com/mwilliamson/mammoth.js#security), [yauzl streaming/size validation](https://github.com/thejoshwolfe/yauzl#api), [inert htmlparser2 DOM parsing](https://github.com/fb55/htmlparser2#usage). Node 24 permissions restrict filesystem/process capabilities but do not provide the newer Node network gate; the release makes no stronger isolation claim.

The mobile preview audit exposed low contrast for completed checklist text and undersized task checkboxes. The shared editor now uses readable completed text, 24-pixel checkboxes within 44-pixel labels, and disabled task inputs in read-only views; no document state changes for this presentation fix. Slow source transfers get a four-minute client deadline separate from the 15-second parser deadline. “Stop waiting for conversion” aborts the wait and retains the same intent; it does not claim to cancel server work or create a page. Late responses cannot replace a retried preview.

This integration companion retains HOLY-9/10 and their combined browser fixtures with distinct editor package next50.9. It must not be promoted as the main-based next50.8 production candidate while live administrator-fixture approval remains pending. Both trees run their own CI. The empty-workspace form also confirms before leaving an unrelated unsaved title to open the completed import.
