# Versioned record layout foundation and renderer (HOLY-40)

The native service remains unexposed pending the approved tenant integration and full record-form host. Current central tenant administrator plus collection schema/view capability manages layouts; no permission is created by arranging a field. Drafts and published pointers are separate, optimistic and operation-idempotent. Immutable layout/publication versions retain actor/time/source metadata; no record values are stored or rewritten.

Layouts reference stable field IDs in at most ten tabs, twenty sections and 110 distinct slots with one/two-column metadata and bounded plain labels/descriptions. Drafts may be incomplete for editing. Exact ten-minute publication previews require name and every active required field in an editable reachable position, current field visibility and current schema/policy/proof. Stale drafts/schema/permissions or final-proof expiry roll publication back. Both active draft and published fields register generic view dependencies, preserving compatibility with migration replays. A schema field must first be optional and placed in the published editable layout before becoming required.

Current reads filter inaccessible/deprecated fields and empty sections/tabs, with current write flags and no values/defaults. Record-level view permission can open the layout without granting collection-wide access. Field rename preserves positions; field deprecation is blocked while active layout dependencies exist. A current schema/layout mismatch disables creation until review.

The reusable React renderer has labelled controls, keyboard Arrow/Home/End tabs, preserved mounted panels, visible focus, 44-pixel controls and a single-column phone layout. A new publication announces availability but does not replace an open form's layout; switching is disabled while unsaved changes exist. Current field revocation removes controls immediately, and actor/record scope changes remount layout state. Host field values must be controlled by the authoritative form draft and the existing session/permission boundary; this renderer is not a substitute for that host.

A synthetic local-only qualification route exists only when HS_LOCAL_PREVIEW=1 and returns 404 otherwise. No business data is persisted there; no production preview flag is enabled. Browser checks at 1100/390 px verify keyboard tabs, exact label/read-only behavior, preservation through publication, phone geometry/no overflow and zero axe WCAG A/AA violations. Service tests cover draft/publication separation, rights, required reachability, sensitivity, schema impacts, retry/stale/expiry, immutable evidence and actual startup migration replay. CI adds real PostgreSQL publication retries/replay, full regression and container gates.

Remaining full story: native layout arrangement/builder UI, binding the renderer to complete authoritative record forms/drafts and real suite permissions, mobile/device and integrated fault/performance qualification. No full HOLY-40 completion is claimed.
